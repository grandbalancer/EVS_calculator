# План разработки и архитектура

Рабочее название: «Подрывное дело — расчётчик». Windows 7 SP1 и выше, русский интерфейс, светлая минималистичная тема, установщик `setup.exe`.

## 1. Принятые решения

| Вопрос | Решение |
|---|---|
| Назначение | Справочник/тренажёр «строго по учебникам». Каждое число и формула привязаны к книге, таблице и странице |
| Автономность | Приложение полностью самостоятельное. Игра разрабатывается отдельно, никакой связи и интеграции с ней нет |
| Язык / стек | C++17, Qt 5.15 LTS (последняя ветка Qt с поддержкой Win7), Qt Widgets + QGraphicsView, CMake |
| Компилятор | MinGW 8.1 из комплекта Qt 5.15.2, 32-бит. Одна сборка работает на 32- и 64-битной Windows 7+. Определяем `_WIN32_WINNT=0x0601`, чтобы нельзя было случайно вызвать API новее Win7 |
| Среда | Разработка на Mac. Сборка и проверка UI на вашем Windows 10/11. Win7 для проверки пока нет, см. риски |
| Редактор ЭВС | Свободное полотно с привязкой к сетке, длина и сопротивление над каждым проводом, шаблоны сетей не нужны |
| Результат ЭВС | Сопротивление и ток, вывод по источнику тока, рекомендации по исправлению |
| Обратный режим | Схема рисуется только при полных данных |
| Схемы зарядов | 2D: план и разрез с размерами, условные обозначения как в учебниках |
| Данные | Свои элементы в базе, сохранение/открытие схем, экспорт PNG/PDF и печать |
| Поставка | Установщик (Inno Setup), `windeployqt` собирает DLL Qt |
| Поддержка | Только я через Claude. Код простой, данные отдельно, много тестов |
| Порядок | Этап 1 ЭВС, этап 2 конструкции, этап 3 грунты |

## 2. Подготовка данных

Книги целиком не читаются: таблицы и разделы достают скрипты, а читаются только нужные листы.

1. `tools/manifest.py`: список таблиц (книга, номер, ключевое слово заголовка, лист) и разделов (диапазоны листов PDF).
2. `tools/extract.py` вытаскивает таблицы в `data/draft/tables/*.csv`. Сканы с плохим текстовым слоем переписываются вручную с картинок в `data/draft/manual/*.csv`, эти файлы имеют приоритет.
3. Страница сверки `tmp/review.html`: слева картинка листа, справа расшифровка. Сверенная пользователем запись получает статус `verified`.
4. Сверенные таблицы переносятся в `data/builtin/*.json`. У каждой записи есть источник и статус сверки.
5. `tools/validate_data.py` проверяет формат, ссылки, совпадение чисел с черновиками и пересчитывает решённые примеры; `tools/digest.py` собирает сводку `docs/data_digest.md`.
6. Методика описывается в паспорте `docs/methods/<имя>.md` (порядок расчёта словами со ссылками на листы). Паспорт согласуется **до** написания кода, код реализует согласованный паспорт.

Принцип: формулы и числа берутся только из источников, не из памяти. Временные файлы (картинки листов, вырезки, страница сверки) лежат в `tmp/` и не коммитятся.

## 3. Архитектура

```
┌─────────────────────── UI (Qt Widgets) ───────────────────────┐
│ MainWindow → вкладки: ЭВС | Конструкции | Грунты              │
│ EvsEditor (QGraphicsView)  формы  панель результата  схемы    │
└──────────────▲─────────────────────────────▲──────────────────┘
               │ контроллеры                  │
┌──────────────┴─────────────────────────────┴──────────────────┐
│ Application: проекты (.evs), undo/redo, экспорт PNG/PDF,      │
│ печать, пользовательские элементы                             │
└──────────────▲─────────────────────────────▲──────────────────┘
┌──────────────┴───────────┐   ┌──────────────┴──────────────────┐
│ Core (чистый C++17,      │   │ Data: каталог элементов          │
│ без Qt)                  │◄──┤ builtin JSON (из учебников)      │
│ domain + calc + drawing  │   │ + пользовательский слой          │
│ Result + CalcTrace       │   │ в %APPDATA%                      │
└──────────────────────────┘   └─────────────────────────────────┘
```

Ключевые решения:

1. **Ядро без UI и без Qt.** Его можно тестировать на Mac без установки Qt 5.15, и оно не зависит от интерфейса.
2. **Данные отдельно от кода.** Таблицы лежат в JSON с источником. Пользовательские элементы лежат в отдельном слое с той же схемой и не затрагивают встроенные данные.
3. **`CalcTrace`.** Каждый расчёт возвращает шаги: формула, подстановка, результат, источник. Это основа для проверки «строго по учебнику» и для тестов. Показ хода решения в интерфейсе можно включить позже, ядро его уже даёт.
4. **Два решателя для ЭВС.** Решатель по методике учебника даёт результат для стандартных сетей (последовательная, параллельная, смешанная). Общий решатель электрической цепи считает произвольную схему со свободного полотна и перекрёстно проверяет первый на стандартных сетях. Если схема не укладывается в методику, программа так и пишет.
5. **Источники разных типов.** Машинки проверяются по таблицам возможностей (схема, число ЭД, сопротивление), батареи, аккумуляторы, станции и сети по потребным току и напряжению. Возможности машинок хранятся в данных, а не в коде.
6. **Один граф для обоих режимов.** Редактор и обратный режим работают с одной моделью `Network`. Обратный режим строит граф и автораскладку и показывает его на том же полотне.
7. **Единый движок чертежей.** Вкладки 2 и 3 строят нейтральную модель `Drawing` (линии, размеры, штриховка, обозначения). Её рисует QGraphicsScene и экспортируют в SVG/PDF.
8. **Без OpenGL.** Программный растеризатор, чтобы не зависеть от драйверов на старых системах.

## 4. Структура репозитория

```
core/         domain, calc, drawing

data/         builtin/*.json, draft/*.csv, schema/
tools/        Python: manifest, extract_tables, review, cut_pages, validate

```

## 6. Риски

- **Win7 не проверяется.** Меры: Qt 5.15 + MinGW, `_WIN32_WINNT=0x0601`, без OpenGL, проверка импортируемых DLL в сборке. Для этапа 8 нужна любая машина или виртуалка с Win7 SP1 (знакомый, старый ноутбук).
- **Качество извлечения таблиц.** Объединённые ячейки и сноски. Меры: отчёт о качестве, HTML-сверка, флаг `verified`.
- **Решённые примеры есть только в Практикуме** (листы 9, 11, 13) и касаются ЭВС. Для вкладок 2 и 3 примеры придётся искать после появления задания. Кроме тестов по Практикуму, делаем перекрёстную проверку двух решателей и граничные случаи.
- **Qt 5.15 на современном macOS.** Ставится не всегда гладко. Поэтому ядро без Qt, а UI проверяем на Windows.
- **Права на таблицы.** Если приложение будет публиковаться, проверьте права на воспроизведение данных из учебников.
- **Вкладки 2 и 3 не описаны.** Объём и формат данных пока неизвестны.

## 7. Предложения по архитектуре и работе (2026-11-15)

Статус: предложено, ждёт вашего решения. Принятые пункты переносятся в раздел 1.

**Данные**

1. **Один источник истины.** Данные живут в `data/builtin/*.json`, сверенных с книгами. Справочник xlsx и страница сверки строятся из JSON, а не правятся параллельно. Сейчас одно и то же число живёт в трёх местах (CSV, xlsx, будущий JSON) и может разойтись.
2. **Статус записи вместо флага `verified`.** Значения: `verified` (сверено вами), `checked` (чистый текст книги, перепроверен по картинке или второй книге), `transcribed` (переписано со скана, ждёт вас), `conflict` (книги расходятся), `derived` (вычислено). Интерфейс показывает всё, что не `verified`, как несверенное, но различает «ждёт сверки» и «книги противоречат».
3. **Значения в единицах книги + исходная строка.** В JSON хранится число, единица как в книге и `raw` (текст из книги: «0,9-1,5», «до 250», «520±20»). Ядро переводит в СИ при загрузке. Так сверка с книгой идёт без пересчёта в уме, а валидатор ловит опечатки переноса.
4. **Возможности машинок это таблица, а не код.** Строка: схема, тип ЭД, максимум ЭД (пар), максимум сопротивления. Проверка источника одна для всех машинок. Новая машинка добавляется пользователем без изменения кода.
5. **Константы методики в данных** (`evs_method.json`): токи по схемам, запас длины, ГЗУ, ограничения, каждая с цитатой. Код решателя только применяет их.
6. **Провод описывает свою «основу сопротивления»** (на жилу или на весь провод) и число жил. Это главный источник ошибки в 2 раза между РПР-69 и Учебником.
7. **Валидатор данных** `tools/validate_data.py` (сделан): схема, листы, совпадение чисел с черновиками, пересчёт эталонных задач. Запускается перед каждой сборкой.

**Расчёт**

8. **Эталонные задачи как данные** (`tests/golden/*.json`, сделано): одни и те же случаи проверяет Python-валидатор сейчас и тесты C++ потом. Хранятся и ответ книги, и верный ответ, расхождения описаны. Уже найдено 3 арифметические ошибки в книгах.
9. **Решатель по методике главный, общий решатель вспомогательный.** Вывод «годится/не годится» даёт только методика. Общий решатель цепи считает токи в каждом ЭД и схемы вне методики (смешанная, неравные ветви) с явной пометкой «вне методики учебника». Сеть со свободного полотна сначала распознаётся как одна из схем методики.
10. **Файл схемы `.evs` хранит снимок использованных элементов** и версию данных, чтобы схема открывалась одинаково после правки базы.

**Работа**

11. **Сборка Windows в облаке.** GitHub Actions с Qt 5.15.2 MinGW 32-бит собирает `setup.exe` на каждый коммит. Вам не нужно собирать самому, только ставить и смотреть интерфейс. Нужен приватный репозиторий на GitHub (решение за вами).
12. **Qt 5.15.2 на Mac через `aqtinstall`** (готовые сборки, без компиляции). Тогда интерфейс можно смотреть и на Mac, Windows нужна только для финальной проверки.
13. **Windows 7 без отдельной машины:** виртуалка UTM с эмуляцией x86 на Mac. Медленно, но для smoke-теста установщика хватит.

15. ~~**CLAUDE.md короче**~~ Сделано 2026-11-15: в CLAUDE.md правила и решения, данные в `docs/data_digest.md`.
